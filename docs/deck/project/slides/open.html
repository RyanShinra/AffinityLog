Issue 17 · request isolation

Requests run at READ COMMITTED. I checked with SHOW transaction_isolation rather than assuming, so one request is not one snapshot. A delete committed between the candidate select and the summary read would null the entire candidates response, because the list is non-null all the way up. Nothing deletes today, so it can't happen yet. I found it by asking what would make it happen.
