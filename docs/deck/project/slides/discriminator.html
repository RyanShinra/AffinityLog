Where the discriminator lives

It isn't in the key, and it isn't in the value. The view works it out per row, from the sibling table.

CASE

WHEN count(cc.id) = 0 THEN 'no chains recorded'

WHEN bool_or(cc.role::text = 'TARGET') THEN 'antibody-target complex'

WHEN bool_or(cc.role::text = 'LIGHT') THEN 'antibody only (H/L pairing)'

ELSE 'single chain (no interface)'

END AS interface_kind

I wrote this one by hand, and the leading count() branch is why. It's a LEFT JOIN, so a candidate with no chain rows still produces a group, and bool_or over zero rows returns NULL rather than false. NULL isn't true, so that row would fall through to the ELSE and get mislabeled silently.
