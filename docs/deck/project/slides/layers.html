The schema

Three layers

1 · The bag

candidates.scores

JSONB, GIN indexed, keyed by the full export header. I store the values as text without coercing them, so a new recipe needs no migration.

2 · The chains

candidate_chains

An antibody is built from two protein chains, heavy and light. The target, HER2, is a third. This table records which ones went into each fold, and that composition is what tells the bag apart.

3 · The catalog

modules / metrics / concepts

What a score means. Display name, unit, direction, value type, and the caveat that has to travel with the number.

Each layer answers something the one before it can't. The bag takes whatever a pipeline emits, but it can't say what a column is. The chains say what was folded, but not what to call it.

JSONB is Postgres storing a whole JSON document in one column, parsed into a binary form rather than kept as text. GIN is an inverted index: it maps each key back to the rows that contain it, the way the index at the back of a book maps a word to its pages.
