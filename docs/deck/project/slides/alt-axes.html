When the header isn't enough

A metric is identified by (module, column_key, variant_kind, variant). The only question a key ever raises is whether the header spells out all four.

Usually it does · 197 of 200 keys

evoprotgrad.esm_pseudolikelihood_ratio
evoprotgrad.amplify_pseudolikelihood_ratio

Two language models, two columns. Which one ran is written into the name, so the key decomposes on its own and one lookup finishes it.

Three keys it doesn't

boltz2.protein_iptm
boltz2.iptm
boltz2.complex_ipde

Which chains were folded belongs to the candidate, never to the header. Three keys times three interface kinds is nine catalog rows, and the resolver has to ask the view which one it has.

I ask the two questions in that order. Looking up first and retrying on a miss is shorter, and works today only because of how the seeders happen to skip rows.
